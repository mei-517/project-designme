## Project

Project DesignMe ("Design your time.") is a calendar app focused on letting users *design* how they spend their time, not just record events. The project is at an early stage: product docs exist, and the backend is a freshly generated Spring Boot skeleton with no domain code yet. There is no frontend yet.

- `docs/01_product_requirements.md` — the PRD (written in Japanese). Read it before designing any feature; it defines the views (Month, Time Design, Week, Day), event model (required: title + time; optional: color, notification, repeat, memo), drag-based editing, time snap units (1h down to 1min), templates, shift/wage management, and per-day memos with images. Non-functional requirements, MVP, and future ideas sections are still empty.
- `docs/00_vision.md` — vision doc (currently empty).

## Backend (`backend/designme-api`)

Spring Boot 3.5 / Java 21 (Gradle toolchain) / Gradle 8.14 wrapper. Dependencies: Spring Web, Spring Data JPA, Bean Validation, Lombok, PostgreSQL driver.

Base package: `com.designme.designme_api` (underscore, as generated by Spring Initializr).

Run commands from `backend/designme-api` (use `gradlew.bat` in cmd/PowerShell, `./gradlew` in Bash):

```bash
./gradlew build                 # compile + test
./gradlew bootRun               # run the API
./gradlew test                  # all tests (JUnit 5)
./gradlew test --tests 'com.designme.designme_api.DesignmeApiApplicationTests'           # one class
./gradlew test --tests 'com.designme.designme_api.DesignmeApiApplicationTests.contextLoads' # one method
```

Note: `application.properties` only sets the app name — no datasource is configured. Because JPA and the PostgreSQL driver are on the classpath, `bootRun` and the `@SpringBootTest` context test will fail until `spring.datasource.*` is configured (or a test database/profile is added).
